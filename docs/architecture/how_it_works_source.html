How NyayaSutra AI Works: One Case, Start to Finish

A plain-English walk-through of what the app does today, using a cheque bounce case.
Only features working today are shown.
Sample case: names and dates are made up.
The caseRamesh Traders received a cheque for ₹2,50,000 from Sunil Kumar. The bank returned it unpaid.
The problemRamesh wants the money and goes to a lawyer.
Key dateBank told Ramesh on 3 March 2026.
Today10 March 2026, the lawyer opens NyayaSutra AI.

1Sign in safely

The lawyer enters a password and a 6-digit phone code.
The app confirms the lawyer's identity and opens a secure session.
Like showing an ID card at the court gate.
Supabase Auth, TOTP MFA, sessions

2Open a private case file

The lawyer creates "Ramesh Traders v. Sunil Kumar".
Only people added to this case can open it, and the database checks this too.
Like a locked cabinet with a list of allowed names.
FastAPI, Postgres row-level security

3Upload the papers

Cheque copy, bank return memo and a Hindi invoice scan.
Each file is checked for hidden harmful content, then stored privately.
Like a security guard checking every bag.
File checks, private Supabase Storage, job queue

4Read every page

The lawyer waits a short while; status shows progress.
Text is pulled out and scans are read by OCR. Unsure words are marked, not guessed.
Like a clerk typing out old papers carefully.
PDFium, RapidOCR, language detection

5Make index cards

This happens automatically.
Papers are split into small labelled pieces. Each keeps its document and page number.
Like a filing clerk's index cards.
Chunking, local fastembed embeddings

6Summarise on request

The lawyer asks for a summary and gives consent.
Parties, amount and dates appear with page links. Details not found on that page are marked unverified.
Like a junior's brief, with page numbers.
Document intelligence, gpt-oss:120b

7Ask a question

"What must we prove under Section 138?"
A fast AI decides the kind of question and rewrites it for searching.
Like a librarian deciding which shelf to visit.
Planner, gpt-oss:20b, allowed tools only

8Search the law five ways

Status shows "Searching…".
By meaning, keywords, exact section, everyday words and names. The best 8 passages are chosen.
Like five researchers comparing notes.
101 acts, 38,152 SC judgments, reranker

9Write from sources only

The answer appears word by word.
Phone, PAN and Aadhaar numbers are hidden first. AI is told to use only the found passages.
Like an open-book exam.
Masking, gpt-oss:120b on Ollama Cloud

10Fact-check the answer

The lawyer sees sources to click and read.
Code checks each cited section and case name. A second AI reviews claims. Weak answers get a warning.
Like a senior checking a junior's citations.
Citation check, Supreme Court case register

11Work out the deadline

"When must the demand notice go?"
Ordinary maths, not AI: 2 April 2026, 23 days left, under Section 138(b). The lawyer adds a reminder.
Like a calculator and a diary.
Limitation tool, calendar reminders

12Draft, review, finish

The lawyer drafts the notice, edits it, exports it.
Missing facts are flagged, not invented. Old chats are deleted on schedule.
Like a first draft on the lawyer's desk.
Drafting, Word and PDF export, retention job

Why the lawyer can trust it

Every answer shows where it came from, down to the passage and page. If nothing supports an answer, the app says so.

How client data stays private

Cases are isolated, every action is logged, and identity numbers are hidden. Names and facts do still go to the AI provider.

Who stays in charge

The lawyer. The app can make mistakes, and it gives no legal advice. Check every result before relying on it.
